# CrmApp

A full-stack CRM built with .NET 10, following Clean Architecture and orchestrated with .NET Aspire.

## Tech Stack

- **.NET 10** (SDK `10.0.201`) with C# and nullable reference types
- **.NET Aspire 13.4** — local orchestration, service discovery, health checks, OpenTelemetry
- **ASP.NET Core** minimal APIs + SPA hosting
- **Entity Framework Core 10** on **PostgreSQL** (Npgsql)
- **MediatR** (CQRS), **AutoMapper**, **FluentValidation**, **Ardalis.GuardClauses**
- **OpenAPI** with **Scalar** interactive API reference

## Architecture

The solution follows Clean Architecture — dependencies point inward, so `Domain` and `Application` have no infrastructure concerns.

| Project | Responsibility |
|---|---|
| `src/Domain` | Entities and core domain logic. No external dependencies. |
| `src/Application` | Use cases (CQRS via MediatR), abstractions, validation. |
| `src/Infrastructure` | EF Core `DbContext`, PostgreSQL, data access, external services. |
| `src/Web` | HTTP API endpoints, OpenAPI/Scalar, SPA host, composition root. |
| `src/Shared` | Cross-cutting constants (e.g. service/resource names). |
| `src/ServiceDefaults` | Aspire shared config: telemetry, health checks, resilience, service discovery. |
| `src/AppHost` | Aspire orchestration — provisions PostgreSQL and runs the services. |

Central build configuration lives in `Directory.Build.props` (target framework, nullable, warnings-as-errors) and `Directory.Packages.props` (Central Package Management — all package versions are pinned here).

## Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download) (`10.0.201` or newer)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — required by the Aspire AppHost to run PostgreSQL

## Getting Started

### Run via Aspire (recommended)

With Docker Desktop running, launch the AppHost. It provisions PostgreSQL and starts the services, exposing the Aspire dashboard:

```bash
dotnet run --project src/AppHost
```

The dashboard URL is printed on startup. The database connection string is generated by Aspire and injected into the Web app automatically — no manual credentials needed.

### Run the Web app directly

You can run the API against your own PostgreSQL instance. Set the connection string in `src/Web/appsettings.json` (or user secrets):

```json
"ConnectionStrings": {
  "CrmAppDb": "Server=127.0.0.1;Port=5432;Database=CrmAppDb;Username=<user>;Password=<password>;"
}
```

Then:

```bash
dotnet run --project src/Web
```

In `Development`, the database is (re)initialised on startup. The API reference is available at `/scalar`.

## Common Commands

```bash
dotnet build            # build the solution
dotnet test             # run all tests
dotnet run --project src/AppHost   # run everything via Aspire
```

## Configuration Notes

- **Package versions** are managed centrally in `Directory.Packages.props`. Add a `PackageReference` (no version) in the project and a matching `PackageVersion` here.
- **Transitive pinning** is enabled, so central versions also constrain transitive dependencies.
